Hospital Price File Audit

Tristan Kennedy · files fetched · code and data

Since April 1, 2026, CMS has required hospitals to add four columns to their published price files. They report the median, 10th and 90th percentile of what insurers actually paid for each service, and the number of claims behind those figures. I checked whether hospitals do this, using a random sample of 300 US hospitals and every non-federal hospital in Virginia.

Method

  • Sample. The frame is 4,397 acute care and critical access hospitals from CMS Hospital General Information, excluding federally owned hospitals, which the rule exempts. 300 were drawn at random within strata, using proportional allocation and seed 20261018. I drew the sample before looking up any hospital's website, so a hospital that can't be found still counts.
  • Collection. For each hospital, the script fetches cms-hpt.txt from its website, finds the hospital's entry and downloads the listed price file. If a server refuses the request, it retries once with a browser user agent. Each file is read from its start, up to 300 MB.
  • Paid amounts reported. This counts hospitals whose median allowed amount is filled in on more than 10% of payer rows where the rate is a percentage or algorithm, which is where CMS asks for it. Files with no such rows are judged on all payer rows. It isn't a pass/fail check: a count of 0 with blank amounts is allowed when the hospital has no claims in the 12 to 15 month lookback, and a file alone can't show whether that's true.
  • Not checked. A check is left blank when an earlier step failed, or when the failure might be mine rather than the hospital's. That covers a "not found" error on a website I looked up, a timeout, or my name matching failing to find the hospital in its index. Blocked requests, broken HTTPS and empty indexes count as failures.
  • Advisory checks are reported but don't count toward a hospital's result. CMS's FAQ allows zipped files. The rule bans barriers like required accounts, but it doesn't clearly ban blocking automated downloads.
  • Related work. Peterson-KFF (October 2026) found counts of 0 in 92 to 95% of commercial percentage and algorithm rates, in schema-compliant files processed by Turquoise Health. This page differs in two ways: hospitals are the unit, and hospitals whose files couldn't be found or read stay in the denominator.
  • Verified twice. Every hospital was fetched again about 8 hours later, early on October 18, with fresh downloads. A failure is shown only if it repeats on both fetches.

Limits

  • Results reflect two fetches on October 17–18, 2026. Hospitals update their files, so a failure here may already be fixed.
  • Website addresses came from DoltHub, HIFLD and some hand lookup. A wrong address shows up as "not checked", not as a failure.
  • Only the first 300 MB of each file is read, so the "filled in" check covers that portion of very large files.
